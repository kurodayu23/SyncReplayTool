# 界面规范（简约、耐看）

> 判断标准只有一句：把界面静置一周再看，还不刺眼、还不土。

## 1. 设计 token（只许用这些，不许各处硬编码）
| 类别 | 取值 |
|---|---|
| 间距阶 | 4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 字号阶 | 12 / 13 / 14 / 16 / 20 / 24 / 32 |
| 行高 | 正文 1.6，标题 1.3 |
| 圆角 | 6 / 10 / 16（同一层级只用一档） |
| 中性色 | 背景 / 表面 / 分隔 / 次要文字 / 主文字，各一档 |
| 强调色 | 一个主色 + 一个语义色（成功/警告/错误） |
| 阴影 | 最多两档：浮层与卡片 |

## 2. 布局
- 一个视口只有一个视觉主角；元素对齐到同一网格。
- 留白优先于分割线；能用间距解决的不用边框。
- 深浅色都要过一遍：深色不许出现纯黑纯白对撞。

## 3. 交互
- 动效 ≤ 200ms，只做位移/透明度，不做弹跳炫技。
- 破坏性操作要二次确认；可撤销的给撤销，不弹确认框。
- 空状态、加载态、错误态三态都要设计，不许留白屏。

## 4. 错误呈现（客人最怕的就是弹窗）
- 绝不把堆栈或异常原文丢给用户。
- 用户输入错 → 就地红字提示；可重试故障 → 一条提示 + 重试按钮；不可恢复 → 一句人话 + 下一步建议。
- 同一错误不许连弹；连续失败要收敛成一条汇总。
